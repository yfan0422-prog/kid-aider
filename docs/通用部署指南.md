# 通用部署指南 — 阿里云轻量服务器

> 基于名片管理系统部署经验提炼，适用于 Python/FastAPI 类项目。其他技术栈需替换对应步骤。

## 三、GitHub SSH 密钥配置（一次性）

> **经验教训**：国内服务器访问 GitHub HTTPS 经常被墙（TLS 错误），SSH 协议更可靠。配置一次，永久使用。

```bash
# 1. 生成 SSH 密钥（如果还没有）
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519

# 2. 查看公钥，复制全部内容
cat ~/.ssh/id_ed25519.pub
```

3. 将公钥添加到 GitHub：打开 https://github.com/settings/ssh/new
4. 选择 **Authentication Key**（不是 Signing Key）
5. 验证连接：

```bash
ssh -T git@github.com
# 看到 "Hi <用户名>! You've successfully authenticated" 即成功
```

## 四、环境变量规划

> **经验教训**：所有敏感信息和可变配置通过 `.env` 文件管理，不写入代码，不提交到 Git。

```bash
# 在项目目录下创建 .env 文件
cat > /opt/<项目名>/.env << 'EOF'
# ========== 数据库 ==========
DATABASE_URL=sqlite:////opt/<项目名>-data/db/app.db

# ========== 数据目录 ==========
DATA_DIR=/opt/<项目名>-data

# ========== 服务配置 ==========
HOST=0.0.0.0
PORT=8000

# ========== 第三方服务密钥（按需填写）==========
# 微信/公众号
WECHAT_APP_ID=your_app_id
WECHAT_APP_SECRET=your_secret

# 阿里云 OSS
OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
OSS_ACCESS_KEY_ID=your_key
OSS_ACCESS_KEY_SECRET=your_secret
OSS_BUCKET_NAME=your-bucket

# AI/大模型 API
OPENAI_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.openai.com/v1

# 其他...
EOF
```

> 🔴 **务必确保 `.gitignore` 中包含 `.env`，防止密钥泄露到 GitHub。**

## 五、项目部署步骤

### 5.1 克隆代码

```bash
cd /opt
git clone git@github.com:<你的用户名>/<你的仓库>.git
cd <你的项目名>
```

### 5.2 创建独立数据目录

> **经验教训**：数据目录必须放在代码目录之外，这样更新代码（git pull / rm -rf）不会影响数据。

```bash
mkdir -p /opt/<项目名>-data/db
mkdir -p /opt/<项目名>-data/uploads
mkdir -p /opt/<项目名>-data/logs
# 根据项目需要添加其他子目录
```

### 5.3 配置环境变量文件

按第四节创建 `.env`，确保 `DATA_DIR` 指向外部数据目录。

### 5.4 安装运行时和依赖

**Python 项目：**

```bash
# 安装 Python 及 venv（仅首次）
apt install python3.12-venv -y   # Ubuntu 24.04
# 或
apt install python3-venv -y      # 旧版 Ubuntu

# 创建虚拟环境
python3 -m venv venv

# 激活并安装依赖
source venv/bin/activate
pip install -r requirements.txt
```

**Node.js 项目：**

```bash
# 安装 Node.js（使用 NodeSource）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs

# 安装依赖
npm install --production
```

### 5.5 手动启动验证

在配置 systemd 之前，先手动启动确认一切正常：

```bash
# Python FastAPI 项目
source venv/bin/activate
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# Node.js 项目
node index.js
# 或
npm start
```

访问 `http://<服务器IP>:8000/` 确认可正常打开。按 `Ctrl+C` 停止。

### 5.6 编写启动脚本

创建 `start_prod.sh`：

```bash
#!/bin/bash
# 生产环境启动脚本
# 使用方式: systemd 调用此脚本

cd "$(dirname "$0")"

# 激活虚拟环境
if [ -d "venv" ]; then
    source venv/bin/activate
else
    echo "错误: 未找到虚拟环境，请先运行部署步骤"
    exit 1
fi

# 确保数据目录存在
if [ -f ".env" ]; then
    DATA_DIR=$(grep -oP 'DATA_DIR=\K.*' .env || echo "data")
    mkdir -p "$DATA_DIR/db" "$DATA_DIR/uploads" "$DATA_DIR/logs"
fi

# 启动服务（根据你的框架调整）
python3 -m uvicorn app.main:app \
    --host 0.0.0.0 \
    --port 8000 \
    --workers 2
```

```bash
chmod +x start_prod.sh
```

### 5.7 配置 systemd 服务

> **经验教训**：不要用 `nohup` 手动后台启动。systemd 能管理生命周期、崩溃重启、开机自启，是生产环境的标准做法。

创建 `your-project.service`：

```ini
[Unit]
Description=你的项目描述
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/<你的项目名>
ExecStart=/opt/<你的项目名>/start_prod.sh
Restart=always
RestartSec=5

# 环境变量也可以在这里设置（与 .env 二选一或互补）
# Environment="DATABASE_URL=sqlite:////opt/<项目名>-data/db/app.db"

[Install]
WantedBy=multi-user.target
```

安装并启动服务：

```bash
# 复制 service 文件到系统目录
cp /opt/<项目名>/<项目名>.service /etc/systemd/system/

# 重载 systemd 配置
systemctl daemon-reload

# 设置开机自启
systemctl enable <项目名>

# 启动服务
systemctl start <项目名>

# 查看状态
systemctl status <项目名>
```

看到 `active (running)` 即部署成功。

## 六、HTTPS 配置（可选但推荐）

### 6.1 使用 Nginx 反向代理 + Let's Encrypt 免费证书

```bash
# 安装 Nginx
apt install -y nginx

# 安装 certbot
apt install -y certbot python3-certbot-nginx

# 获取证书
certbot --nginx -d your-domain.com

# 证书会自动续期，可手动测试续期
certbot renew --dry-run
```

### 6.2 Nginx 配置模板

```nginx
# /etc/nginx/sites-available/your-project
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # 上传文件大小限制
    client_max_body_size 50M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
# 启用站点
ln -s /etc/nginx/sites-available/your-project /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

## 七、日常更新流程

> **经验教训**：代码和数据分离后，更新极其简单 — 一个 git pull + 重启即可。

### 7.1 标准更新（三步法）

```bash
# 第一步：SSH 登录服务器
ssh root@<服务器IP>

# 第二步：拉取最新代码并重启服务
cd /opt/<项目名> && git pull && systemctl restart <项目名>

# 第三步：验证
systemctl status <项目名>
# 浏览器访问确认功能正常，必要时 Ctrl+Shift+R 强制刷新
```

### 7.2 一键更新脚本

将以下内容保存为 `update.sh`：

```bash
#!/bin/bash
set -e

cd "$(dirname "$0")"

echo "📦 备份当前数据..."
BACKUP_NAME="backup_$(date +%Y%m%d_%H%M%S).tar.gz"
DATA_DIR=$(grep -oP 'DATA_DIR=\K.*' .env 2>/dev/null || echo "/opt/$(basename $(pwd))-data")
if [ -d "$DATA_DIR" ]; then
    tar -czf "$BACKUP_NAME" -C "$DATA_DIR" . 2>/dev/null || true
    echo "   备份已保存: $BACKUP_NAME"
fi

echo "🔄 拉取最新代码..."
git pull

echo "🔄 重启服务..."
systemctl restart $(basename $(pwd))

echo "✅ 更新完成！"
systemctl status $(basename $(pwd)) --no-pager -l
```

```bash
chmod +x update.sh
# 以后更新只需：
./update.sh
```

## 八、⚠️ 数据安全红线

```
数据目录 /opt/<项目名>-data      代码目录 /opt/<项目名>
      ↑                                    ↑
   永久保留                            可以随便删
  （数据库、上传文件、日志）            （纯代码，Git 管理）
```

### 🔴 绝对禁止

```bash
# ❌ 永远不要直接删除项目目录！可能包含数据！
rm -rf /opt/<项目名>

# ❌ 不要把数据放在项目目录内的 data/ 下
#    否则 git pull 虽然不删，但 rm -rf 项目时会一并丢失
```

### 🟢 正确做法

- 数据目录通过 `.env` 中的 `DATA_DIR` 指向项目外
- 代码更新只用 `git pull`，不动数据目录
- `.gitignore` 中忽略 `.env` 和 `data/`

## 九、数据备份策略

### 9.1 手动备份

```bash
# 备份整个数据目录
tar -czf backup_$(date +%Y%m%d_%H%M%S).tar.gz -C /opt/<项目名>-data .

# 仅备份数据库
cp /opt/<项目名>-data/db/app.db /opt/<项目名>-data/db/app.db.bak.$(date +%Y%m%d)
```

### 9.2 自动备份脚本

```bash
#!/bin/bash
# 保存为 /opt/<项目名>/backup.sh

DATA_DIR="/opt/<项目名>-data"
BACKUP_DIR="/opt/<项目名>-backups"
RETENTION_DAYS=7   # 保留最近 N 天的备份

mkdir -p "$BACKUP_DIR"

BACKUP_FILE="$BACKUP_DIR/backup_$(date +%Y%m%d_%H%M%S).tar.gz"
tar -czf "$BACKUP_FILE" -C "$DATA_DIR" .

echo "✅ 备份完成: $BACKUP_FILE"

# 清理旧备份
find "$BACKUP_DIR" -name "backup_*.tar.gz" -mtime +$RETENTION_DAYS -delete
```

### 9.3 定时备份（crontab）

```bash
# 编辑 crontab
crontab -e

# 添加：每天凌晨 2 点自动备份
0 2 * * * /opt/<项目名>/backup.sh >> /var/log/backup.log 2>&1
```

```bash
# ========== 服务管理 ==========
systemctl status <项目名>       # 查看服务状态

# ========== 进程管理 ==========
```

## 十一、阿里云安全组配置

> **经验教训**：阿里云默认安全组不开放非标准端口，会导致外部无法访问。

1. 登录阿里云控制台 → 轻量应用服务器 → 选择实例
2. 点击「防火墙」标签
3. 添加规则：

| 端口 | 协议 | 用途 |
|------|------|------|
| 22 | TCP | SSH 远程登录 |
| 80 | TCP | HTTP（如使用 Nginx） |
| 443 | TCP | HTTPS（如使用 Nginx） |
| 8000 | TCP | 应用端口（如直接暴露） |

> ⚠️ 如果你用的是 **ECS** 而非轻量服务器，入口在「安全组」而非「防火墙」。

## 十二、故障排查速查表

| 现象 | 检查命令 | 常见原因 |
|------|----------|----------|
| 网站打不开 | `curl -sL http://localhost:8000/ \| head -5` | 服务未启动、端口不对 |
| 外部无法访问 | `curl -sL http://<公网IP>:8000/` 从本地执行 | 安全组未开放端口 |
| 服务状态 failed | `systemctl status <项目名>` | .env 缺失/错误、依赖未安装 |
| 端口不通 | `ss -tlnp \| grep 8000` | 服务未监听、被其他进程占用 |
| git pull 失败 | `ssh -T git@github.com` | SSH 密钥过期、网络不通 |
| push/pull TLS 错误 | `git remote -v` 显示 https:// | 改为 SSH：`git remote set-url origin git@github.com:...` |
| 功能没更新 | 浏览器 Ctrl+Shift+R | 浏览器缓存了旧文件 |
| 磁盘满 | `df -h` | 日志/备份文件过大，清理旧文件 |
| 内存不足 | `free -h` | 减少 worker 数量、释放缓存 |
| 虚拟环境报错 | `which python3` | 未激活 venv、venv 路径错误 |

## 十三、部署经验教训汇总

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 🔴 **数据丢失** | 项目目录被整体删除，数据目录 `data/` 在项目内 | 数据目录移到项目外，代码和数据物理隔离 |
| 🔴 **密钥泄露** | `.env` 被提交到 GitHub | `.gitignore` 加 `.env`，部署时手动创建 |
| `git pull` 失败（TLS 错误） | 国内服务器访问 GitHub HTTPS 被干扰 | 改用 SSH 协议（`git@github.com:...`） |
| `scp` 上传超时 | 阿里云安全组未开放 SSH 给外部 IP | 不走 scp，代码通过 GitHub SSH 同步 |
| `python3-venv` 未安装 | 阿里云 Ubuntu 最小化安装 | `apt install python3.12-venv -y` |
| systemd 路径错误 | service 文件中的路径写死为旧路径 | 使用 `WorkingDirectory` 绝对路径 |
| nohup 进程残留 | 手动启动后未停止就部署新版 | 部署前 `pkill -f <进程名>` 清理 |
| 端口被占用 | 旧进程未正确退出 | 检查 `ss -tlnp`，先 stop 再 start |
| 静态资源 404 | Nginx 未配置静态文件路径 | 添加 `location /static/` 配置块 |
| 上传大文件失败 | Nginx 默认限制 1M | 设置 `client_max_body_size 50M` |
